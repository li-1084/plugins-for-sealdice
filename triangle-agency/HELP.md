# Triangle Agency Help

`Triangle Agency` 的完整中文帮助文档。

## 安装

1. 下载 `triangle-agency.ts`。
2. 在 SealDice 中上传并加载脚本。
3. 需要使用规则模板时，执行 `.set ta` 切换到三角机构。

如果你只是想快速确认插件有没有正常加载，可以直接输入 `.tahelp`。

## 快速开始

1. 用 `.set ta` 切换到三角机构模板。
2. 用 Sealdice 标准 `.st` 语法录入角色属性与状态。
3. 用 `.tas` 查看当前角色卡是否已经录入完成。
4. 用 `.ta <属性>` 发起资质检定，或用 `.tr <属性>` 发起现实改写。
5. 如果检定进入三重升华或 QA 阶段，按提示继续使用 `.tatr` 或 `.taqa`。
6. 需要查看群内混沌时，用 `.tcs`；需要自定义文本时，用 `.taflavor`。

## 指令速查

- `.set ta`
  - 切换到三角机构规则模板。
- `.tas`
  - 查看自己的角色卡。
- `.tas @某人`
  - 查看他人的角色卡。
- `.ta <属性>`
  - 发起资质检定。
- `.tr <属性>`
  - 发起现实改写。
- `.ta <数值>` / `.tr <数值>`
  - 进行测试投掷，只看结果，不进入完整流程。
- `.tatr a` / `.tatr b` / `.tatr c`
  - 在三重升华阶段选择分支。
- `.tatr quit`
  - 放弃当前三重升华流程。
- `.taqa <数值>`
  - 在 QA 阶段调整成功数。
- `.taqa quit`
  - 结束 QA 阶段并结算。
- `.tcs`
  - 查看当前群内混沌值。
- `.tcs <数值>`
  - 调整当前群内混沌值。
- `.tcst <数值>`
  - 直接设置当前群内混沌值。
- `.taflavor list`
  - 查看当前可配置的风味文字。
- `.taflavor set <键名> <文字>`
  - 设置指定键名的风味文字。
- `.taflavor reset <键名>`
  - 重置指定键名。
- `.taflavor reset all`
  - 重置全部风味文字。
- `.tahelp`
  - 查看插件内置速查帮助。

## 详细说明

### 角色卡与规则模板

- `Triangle Agency` 使用 `.set ta` 注册的规则模板。
- 角色属性与状态沿用 Sealdice 自带的 `.st` 录入方式。
- 插件内部固定使用九项核心属性：
  - `专注`、`欺瞒`、`活力`
  - `共情`、`主动`、`坚毅`
  - `气场`、`专业`、`诡秘`
- 另外还会用到三个状态属性：
  - `过载`
  - `嘉奖`
  - `申诫`

### 检定与流程

- `.ta <属性>` 用于资质检定。
- `.tr <属性>` 用于现实改写。
- 当你使用属性检定时，插件会记录这次投掷的临时状态，并根据结果决定是否进入后续阶段。
- 可能出现的后续阶段有两类：
  - 三重升华：使用 `.tatr a/b/c` 选择分支。
  - QA 调整：使用 `.taqa <数值>` 调整成功数，或用 `.taqa quit` 结束。
- `.ta <数值>` 与 `.tr <数值>` 则属于测试投掷，不会进入完整流程，只适合临时试骰。

### 混沌值

- 混沌值使用群变量保存，属于群级资源，不是个人属性。
- `.tcs` 只查看当前混沌值。
- `.tcs <数值>` 用于调整混沌值，逻辑是“当前值减去输入值”：
  - `.tcs 3` 表示消除 3 点混沌。
  - `.tcs -3` 表示增加 3 点混沌。
- `.tcst <数值>` 则会直接把混沌值设为指定数值。

### 风味文字配置

- `.taflavor` 用于管理群内的风味文字模板。
- 所有配置都是按群保存的，不会全局覆盖其他群。
- 建议先执行 `.taflavor list` 看清楚可用键名，再决定要改哪一项。
- 修改完成后，新的文本会直接影响后续检定、角色卡或提示信息的输出。

## 机制说明

- 插件不支持代骰。
  - 这是因为 `.ta` / `.tr` 的后续阶段依赖进行中的状态记录，代骰会让操作者和被代骰者的状态归属混乱。
- 三重升华与 QA 调整都依赖内存中的临时状态。
  - 发起新投掷、插件重载或流程结束后，当前状态会被覆盖或清除。
- 混沌值使用群变量维护。
- 过载等角色属性依赖角色卡属性存储。

## 常见问题

### 为什么 `.ta @某人` 或 `.tr @某人` 不可用？

因为这个插件的完整流程要依赖一次检定的后续状态，而这些状态是按“当前群 + 当前玩家”记录的。代骰会让后续 `.tatr` / `.taqa` 很难判断该由谁继续操作，所以插件明确禁止了代骰。

### 为什么我刚才已经投过了，但现在 `.tatr` 或 `.taqa` 提示没有状态？

这通常有三种原因：

- 你已经发起了新的 `.ta` 或 `.tr`，旧状态被覆盖了。
- 插件被重新加载了，内存中的临时状态消失了。
- 上一个流程已经结算完成，状态被清理了。

### `.tahelp` 和这份帮助文档有什么区别？

- `.tahelp` 适合在聊天窗口里快速查指令。
- 这份帮助文档负责给出更完整的说明，包括流程、限制和常见问题。
